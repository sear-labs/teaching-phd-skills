# M1 — The Workbench

**Tier:** Year 1

The five surfaces you actually work on, plus the habit that makes all of them safe.

Two threads run through the milestone. **Verification** — every skill ends by checking a result
against something you knew independently, which is the only habit that makes AI assistance
survivable. And **portability** — a result that exists only on your machine, in your head, or in
an unsaved cell is not yet a result.

This is the milestone most likely to feel beneath a third-year student. Take it anyway if you
have not. The checking habit is the thing, and it does not arrive on its own.

## The five skills

| Skill | Channel | Turn in as |
|---|---|---|
| Spreadsheet discipline | arithmetic | .xlsx plus annotation, WA entry |
| Notebooks and AI assistance | arithmetic | notebook link plus verification table |
| The command line and a remote machine | arithmetic | terminal transcript plus retrieved output |
| LaTeX and Overleaf | writing | Overleaf link plus compiled PDF |
| Sanity checks and orders of magnitude | arithmetic | text entry, WA entry |

### Order

**The command line comes before M2.** Skills 06 and 09 both assume shell fluency, and the code
standard presumes it rather than teaching it. If you are starting M2 soon, take this one first.

**Sanity checks is three hours and catches the most expensive class of error in the
curriculum** — the one where the code is correct and the number is wrong. Take it early and it
pays for itself repeatedly.

LaTeX sits here rather than with the writing milestone because it is a tool, learned the way the
terminal is learned. What you *say* in a paper is M3 and M4.

## How you turn this in

**Nothing new gets made for this.** All five skills were already submitted as ordinary
weekly log entries, each one replacing that week's WR, WW or WA. This submission just tells me
where to find them.

**Paste this straight into the text box of this assignment.** No attachment is needed — the
artifacts are already sitting in the weekly entries you link to.

One line per skill: the skill, which entry it went in, the week, and where the artifact is.

```
Spreadsheet discipline                 WA3   week of 8 Sep   github.com/you/thesis
Notebooks and AI assistance            WA5   week of 22 Sep  same repo, see README
The command line and a remote machine  WA7   week of 6 Oct   attached to that entry
LaTeX and Overleaf                     WW9   week of 20 Oct  Overleaf link in that entry
Sanity checks and orders of magnitude  WA11  week of 3 Nov   PDF attached to that entry
```

Then **one paragraph, 150 words maximum**: which of the five was hardest, and why. Not
what you did — you already wrote that. What was hard about it.

That is the whole submission. It should take ten minutes.

### How it is graded

**Complete / redo.** Redo means one or more competency checks did not pass. I will name which
skill and which check, and **you redo only that skill** — not the milestone, and not the others.
A milestone marked complete is complete permanently; it does not repeat in a later semester.

[**The whole curriculum on one page**](https://sear-labs.github.io/teaching-phd-skills/handbook/curriculum.html) — every skill with the exact artifact it wanted
and the checklist it was graded against. Use it to confirm you have everything before submitting.
