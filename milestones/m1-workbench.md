# M1 — The Workbench

**Tier:** Year 1

The five surfaces you actually work on, plus the habit that makes all of them safe.

Two threads run through the milestone. **Verification** — every skill ends by checking a result
against something you knew independently, which is the only habit that makes AI assistance
survivable. And **portability** — a result that exists only on your machine, in your head, or in
an unsaved cell is not yet a result.

This is the milestone most likely to feel beneath a third-year student. Take it anyway if you
have not. The checking habit is the thing, and it does not arrive on its own.

### Order

**The command line comes before M2.** Skills 06 and 09 both assume shell fluency, and the code
standard presumes it rather than teaching it. If you are starting M2 soon, take this one first.

**Sanity checks is three hours and catches the most expensive class of error in the
curriculum** — the one where the code is correct and the number is wrong. Take it early and it
pays for itself repeatedly.

LaTeX sits here rather than with the writing milestone because it is a tool, learned the way the
terminal is learned. What you *say* in a paper is M3 and M4.

## How you submit this

This submission is an **index, not new work.** Every skill was already submitted as an ordinary
weekly log entry. Here you are telling me where to find them.

For each skill, one line:

```
<skill name> — submitted in <WR/WW/WA number>, week of <date> — <link or "attached to that entry">
```

Then one paragraph, no more than 150 words: **which was hardest, and why.**

Graded **complete / redo**. Redo means one or more competency checks did not pass; I will name
which, and you resubmit only that skill. A milestone you have completed is completed
permanently — it does not repeat in a later semester.
